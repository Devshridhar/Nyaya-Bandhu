3. ENTERPRISE SECURITY, ENCRYPTION & OPEN-WORLD HARDENING
====================================================================
1. Authenticated Field-Level Encryption (`AES-256-GCM`):
   - Encrypt all PII fields (`encrypted_transcript`, `encrypted_ocr_data`, `encrypted_facts`, `encrypted_user_contact`) using `cryptography.hazmat.primitives.ciphers.aead.AESGCM` with a unique 12-byte random nonce per write.
   - Store a deterministic `user_contact_hash` and `utr_hash` using HMAC-SHA256 so the system can look up active sessions on WhatsApp and detect duplicate claims for the same transaction without decrypting the database.
2. Input Validation & Malware/Exploit Defense:
   - Validate uploaded files by inspecting magic bytes/headers (only allow `.wav`, `.mp3`, `.ogg`, `.m4a`, `.webm` for audio; `.jpg`, `.jpeg`, `.png`, `.webp` for images).
   - Enforce strict file size limits (Max 10MB per image/audio file, Max 3 screenshots per request).
   - Strip all EXIF/metadata from uploaded screenshots via `Pillow` before storing or passing to Vision APIs.
3. Prompt Injection & Guardrails:
   - Wrap all user transcripts and OCR text in strict XML tags (`<user_evidence>...</user_evidence>`) and instruct the system prompt to ignore any instructions inside those tags that attempt to override legal drafting rules, fabricate claims, or exfiltrate system prompts.
4. Rate Limiting & Wallet Protection:
   - Use `slowapi` to enforce max 10 intake/reply requests per hour per user hash and 60 requests per minute globally to prevent OpenAI/Twilio credit exhaustion.
5. Idempotency Engine:
   - Track `Idempotency-Key` headers on REST calls and `MessageSid` on Twilio WhatsApp webhooks in `IdempotencyRecord` so network retries never trigger double AI billing or duplicate emails to Nodal Officers.

4. DATABASE SCHEMA & STATE MACHINE (`models/domain.py`)
====================================================================
Use SQLAlchemy with WAL-mode enabled on SQLite (and seamless `DATABASE_URL` compatibility for PostgreSQL) to prevent database lockups under concurrency:
1. `GrievanceCase`:
   - `id` (UUID, PK), `case_reference` (Human-readable ID, e.g., `NB-2026-XXXX`)
   - `user_contact_hash` (Indexed String), `encrypted_user_contact` (Text)
   - `status` (Strict Enum: `INTAKE_RECEIVED`, `AWAITING_MISSING_INFO`, `READY_FOR_USER_REVIEW`, `APPROVED_AND_FILING`, `FILED_COMPLETE`, `PURGED`)
   - `detected_language` (String: `hi`, `hinglish`, `en`, `ta`, `te`, `bn`, `mr`, etc.)
   - `encrypted_transcript` (Text), `encrypted_ocr_json` (Text), `encrypted_facts_json` (Text)
   - `utr_or_invoice_hash` (Indexed String, nullable - prevents duplicate filing of the same UTR)
   - `missing_fields` (JSON list), `follow_up_question_native` (Text), `follow_up_count` (Int, max 5 turns)
   - `legal_draft_en` (Text), `draft_summary_native` (Text)
   - `nodal_email_payload` (JSON: `to_email`, `cc_email`, `subject`, `body_html`, `body_text`, `delivery_status`)
   - `pdf_bundle_path` (String), `pdf_size_bytes` (Int)
   - `nch_docket_number` (String, nullable)
   - `version` (Int, optimistic locking), `created_at` (DateTime), `expires_at` (DateTime)
2. `AuditLog`:
   - Immutable log of state transitions (`case_id`, `previous_status`, `new_status`, `actor`, `timestamp`, `metadata_json` with zero PII).
3. `NodalDirectory`:
   - Pre-seed on startup with 25+ major Indian merchants across E-Commerce (Amazon India, Flipkart, Myntra, Meesho, Nykaa), Quick Commerce/Food (Zomato, Swiggy, Zepto, Blinkit, BigBasket), Telecom (Jio, Airtel, Vi, BSNL), Travel (IRCTC, MakeMyTrip, Goibibo, IndiGo, Ola, Uber, Rapido), and UPI/Fintech (Paytm, PhonePe, Google Pay, Razorpay) including their official Grievance/Nodal Officer emails, statutory turnaround times, and sector classification.

5. FAULT-TOLERANT AI PIPELINE (`services/`)
====================================================================
Wrap all external API calls with `tenacity` (`@retry(stop=stop_after_attempt(3), wait=wait_exponential(multiplier=1, min=2, max=10))`) and timeouts:
1. `speech_service.py`:
   - Accepts voice notes (including WhatsApp `.ogg` Opus audio).
   - Primary: Async OpenAI Whisper (`whisper-1`) with Indian context prompt hinting (common UPI/consumer terms: "UTR", "refund", "failed", "Swiggy", "Flipkart", "Rs", "deducted", "Nodal").
   - Fallback: Bhashini ULCA ASR pipeline (`services/inference/pipeline`) if configured or if primary fails.
2. `vision_service.py`:
   - Sends sanitized UPI/invoice screenshots to `gpt-4o` Vision using **Structured Outputs** (`Pydantic` schema):
     - `is_valid_receipt_or_screenshot` (bool)
     - `image_quality_issue` (nullable string - flags if image is too blurry/cropped to read digits)
     - `merchant_name` (nullable string)
     - `claim_amount_inr` (nullable float)
     - `transaction_date` (nullable string in DD/MM/YYYY)
     - `utr_or_order_id` (nullable string - strict verbatim extraction of 12-digit UPI UTR or Order ID)
     - `payment_status_shown` (nullable string)
3. `legal_agent.py` (ZERO-HALLUCINATION RULE):
   - Combines historical case facts + new transcript + new OCR output.
   - Enforces a deterministic check on 5 mandatory facts:
     1. `merchant_name`
     2. `claim_amount_inr`
     3. `transaction_date`
     4. `utr_or_order_id`
     5. `grievance_description` (what went wrong and what remedy is sought)
   - STRICT GUARDRAIL: If the OCR confidence is low, an image is blurry, or any of the 5 mandatory facts are missing or contradictory, the AI MUST NOT guess or invent placeholders. It must transition the case to `AWAITING_MISSING_INFO` and generate a warm, empathetic follow-up question in the user's exact language/script (e.g., Devanagari Hindi or conversational Hinglish) asking ONLY for the missing item(s).
   - Once all 5 facts are verified, transition to `READY_FOR_USER_REVIEW` and generate via Structured Outputs:
     a) `legal_draft_en`: A formal legal notice and NCH complaint under the **Consumer Protection Act, 2019** (citing Section 2(11) Deficiency in Service, Section 2(47) Unfair Trade Practice, Consumer Protection (E-Commerce) Rules 2020, and RBI Turnaround Time (TAT) circulars for failed UPI transactions if applicable). Demand resolution within 7 days prior to e-Jagriti commission escalation.
     b) `draft_summary_native`: A bulleted, plain-language summary in the user's native language stating the Merchant, Amount, Date, UTR/Order ID, and Legal Demand, ending with a clear prompt: "Reply YES / हाँ to approve and send this complaint, or tell us what to change."
     c) `nodal_email_payload`: Formal escalation email matched against `NodalDirectory`.

7. API ENDPOINTS & OMNI-CHANNEL USER CONNECTION (`api/v1/`)
====================================================================
1. `GET /healthz` and `GET /readyz`:
   - Checks DB connectivity, encryption key availability, and configured API keys (OpenAI, Twilio, Email, Bhashini) without exposing secrets.
2. `POST /api/v1/cases/intake`:
   - Multipart upload (`audio`, `text`, `screenshots`, `user_contact`, `preferred_language`).
   - Creates case, runs STT + Vision OCR + Legal Agent evaluation, returns structured state (`case_reference`, `status`, `extracted_facts`, `missing_fields`, `follow_up_question_native`, or `draft_summary_native` + `legal_draft_en`).
3. `POST /api/v1/cases/{case_reference}/respond`:
   - Accepts follow-up voice note, text, or replacement screenshot. Updates facts, re-evaluates completeness, or applies user-requested edits to an existing draft.
4. `POST /api/v1/cases/{case_reference}/approve`:
   - Requires explicit user confirmation (`approved: true`).
   - Compiles the `<2MB` PDF bundle, sends the Nodal Officer email, transitions status to `FILED_COMPLETE`, and returns the downloadable PDF link + step-by-step NCH filing guide (1915 / WhatsApp 8800001915 / consumerhelpline.gov.in).
5. `GET /api/v1/cases/{case_reference}/pdf`:
   - Streams the generated NCH-ready PDF bundle with proper `Content-Disposition` headers.
6. `PATCH /api/v1/cases/{case_reference}/docket`:
   - Records the official NCH Docket Number returned by the government portal.
7. `DELETE /api/v1/cases/{case_reference}/purge`:
   - Immediate cryptographic erasure of all encrypted PII and deletion of local PDF/image artifacts.
8. `POST /api/v1/webhooks/whatsapp`:
   - Production Twilio WhatsApp Webhook handler:
     - Validates `X-Twilio-Signature` header when `ENFORCE_TWILIO_SIGNATURE=true`.
     - Downloads incoming WhatsApp media (`MediaUrl0`, `MediaContentType0` — voice notes & images) asynchronously using basic auth (`TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`).
     - Looks up active case by `user_contact_hash`.
     - If user sends "NEW" or "नया", starts a fresh case.
     - If case is in `READY_FOR_USER_REVIEW` and user replies "YES", "APPROVE", "HAAN", or "हाँ", triggers PDF generation + Nodal email dispatch and replies with the PDF link and NCH instructions.
     - Otherwise, feeds the voice note/image/text into the active case pipeline and replies in the user's native language via TwiML / Twilio REST client.
